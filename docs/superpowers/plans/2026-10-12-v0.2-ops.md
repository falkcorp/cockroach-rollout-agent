# v0.2.0 ops batch: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans.
> The user chose native, inline execution.

**Goal:** Add three things to the existing agent and web UI:

- **Decline** for proposals;
- a cached **release catalog** with a Releases panel;
- a **settings diff** on proposals;
- staged, approved, cluster-distributed **UI certificates**.

**Architecture:** Each operator action lives in `ops.rs` (prechecks) or a new
focused module, and gets a CLI and a web entry point. New tables are added in
`ensure_schema`. The leader does every outbound fetch and writes the results
to the DB. The UI only reads the DB.

**Spec:** `docs/superpowers/specs/2026-10-12-v0.2-ops-design.md`

## Global Constraints

- **Rust and crypto.** MSRV 1.88. ring only: `cargo tree -i aws-lc-rs` must
  print nothing.
- **Every changed file:**
  - version header bumped, `last-edited: 2026-10-12`;
  - conventional commits;
  - a changelog fragment in `changelog.d/`, a TODO fragment in `todo.d/`.
- **Gates:** `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`
  and `cargo test` stay green; `cargo audit` passes.
- **UI escaping.** UI HTML goes through `render::escape`. Every POST needs a
  session and CSRF.
- **No secrets** in events or the audit log: no setting values, no key
  material.
- **Decline** binds to the rollout id. **Cert approve and reject** bind to
  the fingerprint.

## Review Focus

1. **Decline while the leader re-proposes.**
   - The same target must never come back. A newer patch must still be
     proposed.
   - The skip event must not be written on every tick.
2. **Release catalog failure modes.** Proposals must keep working with an
   empty catalog (first boot) and when GitHub is unreachable. A stale
   catalog must not block a proposal.
3. **Settings diff with a missing or unexecutable target binary.** The
   proposal must still be published, carrying an error warning that has to
   be acknowledged.
4. **A cert that fails a node's own SAN check.** That node must keep its old
   cert and report an error, not drop TLS. The other nodes still install it.
5. **Hot reload.** It must not break in-flight connections or require a
   restart. A reload failure leaves the old config serving.

## Task 1: Decline

**Files:** `src/rollout.rs`, `src/cluster_view.rs`, `src/ops.rs`,
`src/main.rs`, `src/web/{mod,db,render}.rs`

**Production changes:**
- `RolloutStatus::Declined` (`"declined"`).
- `OpenSummary` gets `id: String` back.
- `AvailableAction::Decline { rollout_id, target }`.
- `ops::decline(cli, client, actor, rollout_id: Option<&str>, reason) -> Result<String>`
  - It refuses unless the open rollout is `proposed` and, when an id is
    given, the ids match.
  - Event: `rollout_declined`.
- `ops::undecline(cli, client, actor, version)` deletes the declined rows for
  that target. Event: `rollout_undeclined`.
- **Proposals:**
  - pure `declined_skip(target, declined: &[Version]) -> bool`;
  - `propose_next_rollout` checks the declined targets before fetching
    release notes.
  - The `proposal_skipped` "declined" note is written only when the latest
    event of kind `proposal_skipped` has a different detail. This uses the
    pure `should_note(last: Option<&str>, detail) -> bool`.
- **Actions.** `available_actions`:
  - proposed → `[approve, decline]`;
  - while anything is open, the restart shows as `RestartBlocked` with its
    reason instead of disappearing.
- **CLI:** `decline [--reason]` and `undecline <version>`.
- **Web:** `WebAction::Decline { rollout_id, reason }`.

**Tests:**
- `decline_needs_a_proposed_rollout_with_the_same_id`, a pure precheck:
  `decline_precheck(open, id)`.
- `a_declined_target_is_not_proposed_again_but_a_newer_patch_is`
  (`declined_skip`).
- `skip_notes_are_not_repeated` (`should_note`).
- `available_actions_follow_the_cluster_state`, updated: proposed gives
  `[approve, decline, restart_blocked]`. Midway active gives
  `[cancel, restart_blocked]`.
- `actions_parse_from_form_fields`, extended with decline (`rollout_id`
  required).
- Render: the decline form carries `rollout_id` and the CSRF token.

## Task 2: Release catalog and Releases panel

**Files:** new `src/releases.rs`, plus `src/main.rs`, `src/cluster_view.rs`,
`src/web/*`

**`src/releases.rs`:**
- `parse_matching_refs(json) -> Result<Vec<Version>>`
  - Keeps `refs/tags/vX.Y.Z` stable versions only; drops `-alpha`, `-rc`
    and `-beta`.
  - Sorted and deduplicated.
- `refresh_due(fetched_age_secs: Option<i64>, requested_age_secs: Option<i64>) -> bool`
  - `fetched_age` is `None` (never fetched), or more than 3600;
  - or a refresh was requested after the last fetch and the last fetch is
    more than 600 old.
- `struct ReleaseLine { line: (u64, u64), latest: Version, mark: LineMark }`,
  where `LineMark` is `Current` | `Proposed` | `Step(n)` | `Newer`.
- `release_lines(current: &Version, versions: &[Version], proposed: Option<&Version>) -> Vec<ReleaseLine>`
  - one row per line at or above the current line, newest first;
  - the steps come from `build_upgrade_steps(current, latest, versions)`.
- DB helpers:
  - `load_catalog(cli, client) -> Option<Catalog { versions, fetched_age_secs, last_error }>`;
  - `store_catalog`, `store_catalog_error`, `request_refresh`.
- Table `release_catalog`:
  - `id INT8 PK DEFAULT 1 CHECK (id = 1)`;
  - `versions_json STRING NULL`;
  - `fetched_at`, `refreshed_requested_at` (both TIMESTAMPTZ NULL);
  - `last_error STRING NULL`.

**`main.rs`:**
- `available_cockroach_versions` uses
  `https://api.github.com/repos/cockroachdb/cockroach/git/matching-refs/tags/v`.
  This URL is derived from `--github-api-url` by replacing the trailing
  `/releases…` or `/tags` part.
- The leader calls `refresh_catalog_if_due` on every tick.
- `next_upgrade_plan` gets a `versions: Option<Vec<Version>>` parameter. The
  daemon passes the cached versions; `plan` and `prepare` fetch live.

**Web:**
- `ClusterView.releases: Option<ReleasesView>`.
- A Releases panel.
- `WebAction::CheckReleases`, which calls `request_refresh`.

**Tests:**
- `matching_refs_keep_stable_versions_only`;
- `refresh_is_due_when_old_or_requested_and_not_throttled`;
- `release_lines_mark_current_proposed_and_path`;
- `tags_url_becomes_matching_refs_url`;
- a render test for the panel and the "checked N min ago" footer.

## Task 3: Settings diff on proposals

**Files:** new `src/settings.rs`, plus `src/main.rs`, `src/cluster_view.rs`,
`src/ops.rs`, `src/web/render.rs`

**`src/settings.rs`:**
- `struct SettingDefault { name, typ, default }`, parsed from
  `gen settings-list --all-settings --format=ndjson`. The keys are
  `Setting`, `Type` and `Default`. Both ndjson and json array input are
  accepted.
- `struct Override { name, typ, value }`, from `SHOW ALL CLUSTER SETTINGS`
  where `origin='override'`, excluding `version`.
- `struct SettingsReport { warnings: Vec<SettingFinding>, info: Vec<SettingFinding>, error: Option<String> }`
- `SettingFinding { name, kind: Removed|DefaultChanged|TypeChanged, from, to }`
  - `from` and `to` are already redacted.
- `diff(overrides, current, target) -> SettingsReport`
- `redact(name, typ, value) -> String`
  - shows the value only for types `b`, `i`, `f`, `d` and `e`;
  - redacts everything else, and always the names on the deny list.
- `gen_settings(binary: &Path) -> Result<Vec<SettingDefault>>`
  - It runs the binary (stdin null) and parses the output.
  - The default list is cached by binary version.

**Proposal flow:**
- Extract the target tarball (the local-arch artifact from the manifest)
  into a tempdir under `layout.versions_dir()`.
- Run `gen_settings` on the target and on the installed binary, then diff.
- Store the result in `manifest.settings_report`
  (`#[serde(default, skip_serializing_if = "Option::is_none")]`).

**Approval:**
- `OpenSummary.settings_warnings: Vec<String>`, one human line per warning.
- `approve_precheck` requires `accept_warnings` when release-note **or**
  settings warnings are non-empty.
- The Approve card lists the settings warnings, plus a collapsed `<details>`
  holding the info lines.

**Tests:**
- `diff_flags_removed_changed_and_retyped_overrides`;
- `unchanged_overrides_are_quiet`;
- `defaults_changes_on_untouched_settings_are_info`;
- `strings_and_denied_names_are_redacted`;
- `ndjson_and_json_both_parse`;
- `approve_requires_ack_for_settings_warnings`;
- `a_failed_diff_is_a_warning`.

## Task 4: UI certificates

**Files:** new `src/uicert.rs`, plus `src/main.rs`, `src/web/*`,
`scripts/install-rollout-agent.sh`, a new
`scripts/cockroach-rollout-agent-ui-cert.{service,timer}` (or templates
emitted by the installer, following the existing pattern),
`docs/security.md`, `docs/deploy.md`. rcgen moves to `[dependencies]` with
ring.

**`uicert.rs`:**
- `Hosts { dns: Vec<String>, ips: Vec<IpAddr> }`, built by
  `hosts_from(agent_ids, gossip_addrs, extra)`.
- `generate_ca(hosts) -> (cert_pem, key_pem)`
  - "Rollout UI CA", ECDSA P-256, 10 years.
  - Name constraints: permitted DNS per host, IP/32 per IP; excluded none.
  - `is_ca` with `pathlen 0`.
- `issue_leaf(ca_cert_pem, ca_key_pem, hosts, days) -> (cert_pem, key_pem)`
  - ECDSA P-256, serverAuth.
- `fingerprint(cert_pem) -> String`: SHA-256 hex of the leaf DER.
- `inspect(cert_pem) -> CertInfo { fingerprint, sans, not_before, not_after, issuer, subject }`
- `validate(cert_pem, key_pem, ca_pem, now) -> Result<CertInfo>`
  - the key matches the cert;
  - the chain verifies under the CA, through rustls' WebPki verifier
    against a single-root store;
  - not expired.
- `covers(info, hostname, ips) -> bool`
- `renew_due(not_after, now, before) -> bool`

**Table `ui_certs`:** as in the spec. The DB fns are `stage`, `staged`,
`approved`, `decide` (approve or reject, keyed by fingerprint, retiring the
previous approved cert), and `key_pem(fp)`.

**CLI** `ui-cert <init-ca|renew|stage|approve|reject|show>`:
- `init-ca` refuses to overwrite.
- `renew --before 30d` only acts on the node with a CA key, under the
  `ui_cert_renew` lease.

**Agent distribution.** The tick runs `sync_ui_cert`:
- approved fingerprint ≠ the one served
  → validate against the CA chain stored in the row
  → `covers(own hostname, own gossip IP)`
  → atomic write to `<agent-root>/ui-certs/node.{crt,key}` (keeping `.prev`)
  → `reload` through a shared `RustlsConfig`.
- The served fingerprint goes into the heartbeat (`ui_cert_fingerprint`).
- Errors go to the agent row's `error`, prefixed `ui cert:`.

**TLS dir resolution.** `ui_tls` prefers `<agent-root>/ui-certs` when its
`node.crt` exists.

**`web::spawn`** returns the `RustlsConfig` handle, so the daemon can reload
it.

**Web:**
- a UI certificate panel:
  - active cert info;
  - the staged cert with a SAN diff;
  - which fingerprint each agent serves;
- upload form: `POST /ui-cert/upload` (multipart is not needed; PEMs in
  textareas, size-capped at 16 KiB each);
- `GET /ui-cert/{fp}/cert.pem` and `/key.pem` (session required; key
  downloads logged);
- `WebAction::UiCertApprove { fingerprint }` and
  `WebAction::UiCertReject { fingerprint }`;
- `GET /ui-cert/ca.crt` (session required).

**Installer:** installs the `.service` and `.timer` units. The service runs
`ui-cert renew` as cockroach with the env file, same sandbox as the agent.
The timer is enabled with `--enable`.

**Tests:**
- `ca_constrains_names_and_ips`: parse the CA and assert NameConstraints
  covers exactly the hosts;
- `leaf_validates_under_its_ca_and_not_under_another`;
- `mismatched_key_is_rejected`;
- `expired_leaf_is_rejected`;
- `a_node_outside_the_sans_is_not_covered`;
- `renewal_due_window`;
- `fingerprint_is_sha256_of_der`;
- a web test: key download needs a session and sends `no-store` plus an
  attachment disposition;
- a web test: approve with the wrong fingerprint is refused;
- `ui_tls_prefers_managed_dir`.

**Manual:** on the Mac, a leaf for a non-constrained name must be rejected
by Safari and Chrome before the docs claim it.
