### Added

#### Decline a proposal

You can now decline a proposed upgrade from the dashboard, or with
`decline` on the CLI. The leader then stops proposing that version. A newer
patch on the same line is still proposed, and `undecline <version>` undoes
the decline.

- **Why:** previously the only choice in the UI was approving the proposal.
  A CLI `cancel` didn't help either, because the next tick proposed the same
  version again.
- **Rolling restart:** while anything is open, the rolling restart now shows
  the reason it is blocked instead of disappearing.

#### Release catalog and Releases panel

- **One API call.** Release discovery makes a single GitHub `matching-refs`
  call, where it used to page through `/tags` ten times. The old method
  silently lost release lines past 1,000 tags; CockroachDB has 976 today.
- **Cached hourly.** The leader caches the list in `release_catalog` once
  an hour. A failed fetch keeps the previous list.
- **Proposals read the cache.** They fetch release notes only for a step
  that will actually be proposed.
- **Releases panel.** The dashboard shows each release line's newest
  patch, the upgrade path, and the time of the last check, with a
  throttled **Check now** button.

#### Settings diff on proposals

Each proposal compares the cluster's overridden settings, read from
`SHOW ALL CLUSTER SETTINGS`, against the defaults of the installed binary
and the target binary, using `cockroach gen settings-list`.

- **Warnings.** Any override that the target removes, retypes, or gives a
  new default becomes a warning. The approver must acknowledge it. A diff
  that cannot run is a warning too.
- **Context.** Other default changes are listed, collapsed.
- **Redaction.** Secret values are always redacted.

#### Managed web UI certificates

- **CA.** `ui-cert init-ca` creates a private Rollout UI CA. Name
  constraints limit it to the cluster's hostnames and node IPs.
- **Staging.** Certificates are staged by `ui-cert renew` (run daily by a
  new timer, on the CA node only), by a dashboard upload, or by
  `ui-cert stage`.
- **Approval.** A person reviews a staged certificate and approves it, by
  fingerprint, from the dashboard or the CLI.
- **Distribution.** Every agent then validates the approved certificate,
  installs it, and hot-reloads its listener without restarting.
- **Why.** macOS rejects CockroachDB's default 5-year node certificates for
  TLS.
